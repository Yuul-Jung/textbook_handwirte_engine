01. 개발 목표와 요구사항 정의

전자교재를 화면에 띄운 상태에서 마우스와 와콤 신티크로 필기하고, 형광펜·도형·텍스트로 설명할 수 있는 웹 기반 판서 도구를 개발한다. 핵심은 교재 제작과 판서 제작을 분리하여 기존 교재 HTML(웹 문서)을 다시 편집하지 않고 활용하는 것이다.

개발 방식

기능 목록을 한 번에 만드는 대신 작은 변경을 구현하고, 이전 기능의 회귀 시험과 실사용 피드백을 연결한다. 초기 버전에서 확인된 실패를 다음 버전의 재현 시험으로 사용한다.

따라 하기 실습

  1. 판서 엔진 실행 페이지를 열고 판서 버튼을 클릭한다.
  2. 교재 본문에 짧은 선을 그리고 F8로 판서를 끈다.
  3. 다시 켠 뒤 기존 판서가 유지되는지 확인한다.

확인 결과 · 교재 읽기와 판서 모드가 분리되고, 끄기는 삭제가 아니다.

이 안내서는 최종 v45 및 확인 가능한 개발 기록을 기준으로 한다. v01~v17의 모든 개별 릴리스 문서는 확보되지 않아 최종 소스의 버전 주석 및 후속 문서에서 확인 가능한 구성만 설명한다.

02. 웹 기반 판서 엔진의 전체 구조

HTML은 교재 구조, CSS(스타일 시트)는 화면 디자인, JavaScript(웹 동작 코드)는 입력·판서 객체·저장을 담당한다. SVG(확장 가능한 벡터 그래픽)는 각 획과 도형, 글자를 벡터 요소로 표시한다. Canvas(캔버스)는 텍스트 폭 측정과 출력 처리 등에 이용된다.

prepare()는 main 하나와 고유한 비중첩 section[id]가 있는지 확인한다. 이미 엔진이 있거나 설정이 충돌하면 초기화를 거부한다. 원본 교재에 속성을 붙이는 대신 별도 설정 script에 외부 연결 정보를 넣는다.

따라 하기 실습

확인 결과 · 원본 하위 트리 보존과 실행 중 DOM 전체 무변경은 서로 다른 요구사항이다.

03. 포인터 입력과 필압 처리

Pointer Events(포인터 이벤트)는 마우스와 펜을 동일한 이벤트 모델로 처리한다. pointerdown에서 유효한 입력을 시작하고, pointermove에서 좌표를 수집하며, pointerup에서 확정한다. pointercancel 및 비정상 입력에서는 미완료 작업을 폐기한다.

pointerdown입력 종류·ID 확인
→
move샘플·필압 수집
→
pointerup마지막 좌표 반영
→
finish(true)확정·저장
→
render화면 갱신

원본 코드 열기

canDraw는 입력 종류와 버튼을 구분한다. samplePressure는 마우스를 기본 1로 처리하고 펜 필압을 0~1로 제한한다. penWidth는 최소 기준 굵기 25%에서 최대 100%까지 변화시키므로 필압이 0에 가까워도 선이 완전히 사라지지 않는다. 펜을 뗄 때 필압 0이 들어오는 경우 마지막 유효 필압을 유지한다.

실패 재현: v27~v30

반복 시험에서 100획 중 99획만 저장되는 간헐 문제가 관측되었다. v29 실패 로그에서는 버튼이 눌린 상태의 lostpointercapture 뒤 정상 pointerup이 나타났다. 기존 캡처 상실 처리에서 획이 취소되는 경로를 찾아 v30에서 창의 캡처 단계 이벤트를 이용한 추적을 추가했다.

원본 코드 열기

v30의 동일 신규 시험은 8/12에서 12/12로 개선되었고 700/700 모의 획을 저장했다. 브라우저 내부에서 캡처가 자연 해제된 모든 원인 또는 물리 와콤의 입력 손실까지 해결되었다는 뜻은 아니다. v30 검증 기록

따라 하기 실습

  1. 펜으로 점·직선·곡선을 각각 그린다.
  2. 마우스와 펜 입력을 번갈아 사용한다.
  3. 필기 중 창 전환 및 Esc를 시험하고 미완료 획과 다음 입력을 구분한다.

확인 결과 · 정상 종료에서 한 번만 확정되고 취소한 작업은 남지 않아야 한다.

04. 좌표계, 오버레이와 교재 배치

포인터의 clientX/clientY는 뷰포트 좌표다. 저장은 앵커의 사각형을 기준으로 정규화한 좌표를 사용한다. 표시할 때 현재 앵커의 위치와 너비·높이로 되돌린다. 정규화 좌표만으로는 본문 자체가 재배치되는 상황을 안전하게 처리할 수 없으므로 layout(배치 정보)과 앵커 추적을 함께 사용한다.

원본 코드 열기

v21은 본문 바깥 배경까지 필기할 수 있도록 페이지 앵커 __yja_page__를 추가했다. v25는 백지 열기/닫기에 따른 기준 높이 변화를 수정했다. v26은 strokeGeometry()를 공통 경로로 사용해 표시·지우개·편집 좌표를 일치시키고 배치가 맞지 않는 획을 안전하게 숨긴다.

따라 하기 실습

  1. 절 안과 여백에 서로 다른 색으로 표시한다.
  2. 스크롤 및 화면 폭 변경 후 위치를 비교한다.
  3. 백지를 열고 닫은 뒤 본문 위치와 기존 획을 확인한다.

확인 결과 · 배치가 달라진 경우 무조건 같은 위치에 억지로 표시하는 것이 아니라 원래 배치와의 정합성을 판단해야 한다.

06. 저장 구조와 데이터 복구

판서는 브라우저 localStorage(로컬 저장소)에 저장되며, 교재·장·개정 정보로 키를 구분한다. 북마클릿은 URL 경로 및 쿼리의 SHA-256 해시와 main HTML 해시를 사용한다. 같은 출처라도 교재 개정이 바뀌면 기록이 분리될 수 있다.

원본 코드 열기

commit()은 현재 상태를 이력에 기록한 후 새 상태를 저장하고 렌더링한다. 이력은 최대 40단계 및 300,000 보존 좌표로 제한된다. 문서 데이터 한도는 4,000획, 획당 10,000점, 전체 150,000점이다.

원본 코드 열기

오류 복구와 동시 탭

v29는 손상 원본을 그대로 내보내거나 :recovery 키에 보존한 뒤 정상 JSON을 검증하여 복구하도록 개선했다. 다른 탭이 데이터를 변경한 경우 자동 덮어쓰기를 막는다. 서버에 저장되는 데이터가 아니며 브라우저 프로필 삭제나 저장 정책에 영향을 받는다.

따라 하기 실습

  1. 시험 교재에서 판서한 뒤 더보기 → 내보내기로 JSON을 백업한다.
  2. 같은 URL을 새로고침하여 판서가 복원되는지 확인한다.
  3. 시험 데이터로만 정상 JSON 불러오기와 실행 취소를 확인한다.

확인 결과 · 교재 식별자·출처가 다르면 자동 승계되지 않으며, 이전 버전 롤백 전 JSON을 백업한다.

07. 배포 구조의 진화: 플러그인에서 북마클릿으로

초기에는 WordPress 플러그인과 인증된 프레임에서 서버 저장을 시험했다. 그러나 실제 교재 파일을 일일이 수정하지 않고 쉽게 실행한다는 요구를 충족하기 위해, 외부 로더·확장 프로그램·사용자 스크립트·북마클릿으로 배포 방식이 진화했다.

단계기술 및 방식착안 사항
v18~20WordPress/PHP 관리자용 시험 플러그인, 서버 저장·버전 충돌실 WordPress·DB·권한 검증은 보류
v31외부 교재, 원본 본문 불변오버레이를 body 외부 구조로 분리
v32~33버전 고정 로더, SRI(자원 무결성), 독립 Pages 시험최초 HTML 연결 필요; 자동 최신 추적 방식 아님
v34Manifest V3 확장, activeTab/scripting교재 변경 없음, ZIP·개발자 모드 필요
v35~36.0.1Tampermonkey 사용자 스크립트 및 자동 업데이트실제 사용자 권한 OFF 확인, 설정 절차 불편
v37~45Bookmarklet(북마클릿): 즐겨찾기에 코드 등록최초 드래그 1회, 페이지별 실행, 공통 주소

브라우저 보안 승인을 웹페이지가 마음대로 해제할 수 없기 때문에 v36의 자동 설치 방식은 사용자의 실제 편의 요구에 맞지 않았다. v37은 브라우저 즐겨찾기라는 기존 기능을 활용하여 설치 절차 자체를 제거했다.

따라 하기 실습

  2. v45 시험 로그를 열고 각 시험의 목적을 구분한다.
  3. 교재의 링크, 코드 복사, 읽기 모드, 판서 모드가 충돌하지 않는지 실제로 시험한다.

이 안내서 작성 시에는 기존 시험 로그와 원격 배포 성공 기록을 대조했다. 새로운 전체 엔진 시험을 실행한 것으로 해석하지 않는다.
